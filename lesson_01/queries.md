# Запросы к коллекции · занятие 1

**Предметная область:** заказы кофейни «Зерно» — напитки и десерты на вынос и с доставкой.
**База и коллекция:** `coffee`, коллекция `orders`.
**Сколько документов:** 5.

---

## 1. Точное совпадение строки

```js
{ city: "Ярославль" }
```

Найдено: **3 из 5**
Что искали: все заказы, оформленные в Ярославле. Поле `city` есть у каждого документа и хранится строкой, поэтому фильтр находит ровно те три заказа.

## 2. Поле внутри вложенного объекта

```js
{ "payment.method": "карта" }
```

Найдено: **3 из 5**
Что искали: заказы, оплаченные картой. Путь через точку обращается к полю `method` внутри вложенного документа `payment`, а не к полю верхнего уровня.

## 3. Элемент массива

```js
{ tags: "срочно" }
```

Найдено: **2 из 5**
Что искали: срочные заказы. Индекс элемента не указывается: MongoDB проверяет, есть ли значение в массиве `tags` хотя бы один раз.

## 4. Оператор сравнения

```js
{ total: { $gt: 1000 } }
```

Найдено: **2 из 5**
Что искали: заказы дороже 1000 ₽. Это `K-1005` на 1300 ₽ и `K-1003` на 1030 ₽.

## 5. Наличие поля

```js
{ comment: { $exists: true } }
```

Найдено: **3 из 5**
Что искали: заказы, к которым оставили комментарий. Поле `comment` есть только у трёх документов из пяти.

## 6. Сломанный запрос

```js
{ city: Ярославль }
```

Что произошло: **ошибка разбора**.

Как это видно на экране: строка запроса подсвечивается как некорректная, кнопка **Find** не срабатывает и результат не появляется — вместо `0 – 0 of 0` Compass показывает сообщение об ошибке разбора документа.

Почему так: `Ярославль` без кавычек — не строковое значение, а имя переменной, которой не существует. Ошибку ловит клиент при разборе, до отправки на сервер. Поэтому она отличается от пустого результата: корректный, но ни с чем не совпадающий фильтр вернул бы `0 – 0 of 0` без всякой ошибки.

## Цена дубликата

В каждом заказе повторяется `city` (и данные клиента: `client.name`, `client.phone`). Если заказов станет двести, то при, например, переезде точки или исправлении названия города придётся обновлять это значение в двух сотнях документов — и легко получить расхождение, когда часть заказов уже с новым городом, а часть со старым.

Повтор всё-таки оставили, потому что город нужен в каждом заказе для фильтра и отчёта, меняется он крайне редко, а отдельная коллекция справочника городов на пяти документах только усложнила бы чтение. Для редко меняющихся данных дублирование дешевле, чем соединение коллекций.

### Замечание про `$exists` и `null`

```
{ comment: { $exists: false } }  → 2
{ comment: null }                → 2
```

На этих данных числа совпали, но это разные запросы: `$exists: false` ищет отсутствие поля, а `comment: null` — и отсутствие поля, и документы, где поле есть со значением `null`. Совпадение здесь случайное: ни в одном документе нет `comment: null`.
